## 4. 需要补充什么

### P0：先解决现有照片的 DMM 接入边界（本项目侧）

1. **统一像素中心约定。** 输入为 edge origin、半像素中心；当前 DMM `clip_coordinates` 的 `+.5*z` 对该 K 会产生 X/Y 各 +0.5 像素的光栅位置偏移，本轮直接数值核对为 `[0.5, 0.5]`。CPU 参考渲染同样按旧整数中心取样。需明确版本与转换位置，验证 CPU/CUDA 投影、XY 归一化和裁剪缩放。不能在数据端暗改 K，也不能重命名阶段三候选 manifest 绕过限制。当前阶段三仍明确输出 `fit_ready=false`。
2. **可用的上下颌模型包与独立初始化。** 合规 bundle、presence 的外部来源，以及不借用真值的整体位姿初始化仍是正式重建输入。当前已记录的阶段二照片联调使用随机权重夹具，不能拿其全 ignore 结果进入拟合。自动均值模型到照片的初始化尚未完成。
3. **遮挡语义贯通。** 源 `input.valid=1` 表示图像采集有效，不能直接解释为“该像素对 DMM 是可信背景”。脸/唇/舌遮挡需由阶段二 RGB 模型预测后变成 ignore；监督诊断可以显式用 GT tissue，但必须命名为 oracle，不能当正式预测。

这些属于消费者实现/模型问题，不能靠多渲染同一患者照片解决。像素约定属于渲染/拟合源码；DMM 先验训练可以独立进行，但当前整个源码指纹绑定严格，若先训练再改渲染源码，需保留训练快照并明确版本兼容，不能绕过加载校验。

### P1：仿真端补充可用于训练/评估的数据

| 必补项 | 原因与执行要求 |
| --- | --- |
| 多患者，继承 DMM 的 train/val/test 划分 | 当前只有一个开发患者，14 张图不能按图像随机拆成独立 train/val。患者的全部视角、光照、装配变体继承同一划分；开发病例保持开发用途。 |
| 后牙可见性覆盖 | 软组织组 17、27 都只有 inferior 一个视角可见。补充真实可见后牙的不同相机方向；同一场景保持牙弓/软组织固定，不能为某张图移走遮挡体。无法可见时如实保留未充分观察状态。 |
| 可见面积与相机基线统计 | 不只统计“出现过”。本轮保存每牙每视图像素数，并用 ≥64 像素作辅助统计分档，非质量门槛。后续结合投影面积、视角差、遮挡比例确定实验门槛。 |
| 不同遮挡程度和明确的缺牙样例 | 现有场景都是 28 牙存在，缺牙与被遮挡没有样本层面的对照；先保证真实存在性和 FDI 正确。开口、软组织变化应作为新 scene，各自内部保持静态。 |
| 严格配对的遮挡对照 | 固定同一牙弓装配、相机与灯，仅改变软组织可见性，另建实验 run；不要覆盖本批。 |
| 逐病例 QC 与正式使用记录 | 扩展数据继续导出当前全部标注、truth、hash、概览；完成必要视觉检查后再记录训练许可。本批 flag 不自动升级。 |

光照、材质、曝光、背景和分辨率变体可在上述项稳定后逐项增加；每个变化记录参数。畸变、景深、运动模糊涉及新输入条件，不应无声明混入当前固定相机、无畸变基线。没有依据为当前任务规定一个“一定够用”的患者数，先按患者扩展小批、检查学习与验证曲线，再决定规模。

### P2：几何真实性与精度验收需要的补充

- 当前 `collision_gate=NOT_IMPLEMENTED`。已有脸—牙冠表面接触为零的记录，不等于上下牙、舌/牙、牙龈及全软组织的体积穿插均已排除。几何实验需补明确的检查范围、方法与失败样本记录。
- 装配是 `synthetic_not_patient_occlusion`，适合验证已知合成场景；不能评价患者真实咬合恢复。真实咬合研究另需配准证据。
- 真值是扫描可用牙冠/牙龈表面，不是完整牙根。评价范围应与模型表面定义对齐。
- 正式重建报告分开可见与未观察区域、逐牙/逐视图图像误差和 world-mm 表面误差。深度、网格、amodal 仅在评价/显式 oracle 中读取。

## 5. 这些照片用于哪种训练

| 用途 | 当前数据是否适合 |
| --- | --- |
| DMM 形状先验训练 | 照片不直接进入该训练；需要单颌三维采样数据。仿真所引用的原始扫描与 DMM manifest 已存在，但本轮没有验收整个三维训练集。 |
| RGB 分割/FDI 编号/遮挡模型 | 已有正确类型的监督，可作开发诊断；正式训练仍缺多患者划分和已验收样本。 |
| GT 掩码驱动的 DMM 优化器诊断 | 数据内容基本齐备，需先解决像素约定、模型包与独立初始化；单独标记 oracle，不混入正常照片推理。 |
| 正式照片端到端三维重建验收 | 未通过：真实预测权重、接入兼容和独立初始化尚有缺口。 |

## 6. 建议推进顺序

先修正并验证像素中心接口，同时让仿真端扩展多患者划分和后牙覆盖；保留现有两个开发样本作为固定回归输入。随后用已训练的两颌 DMM 加显式 oracle 掩码验证优化器，再接入 RGB 预测并分别报告分割误差与重建误差。先验训练、照片监督模型训练与单病例拟合分别记录，不能互相代替验收。

本轮不改源图、源标签、原始相机、训练划分、训练许可或已有结果。
